Execution metadata on the durable log — token usage and step wall-clock, recorded where a fold/export can read them back. `ModelDelta`'s terminal `done` gains `usage?: ModelUsage`, whose semantic contract is pinned: `inputTokens` is the TOTAL input the call consumed, cache reads/writes INCLUDED (providers disagree — OpenAI/Gemini headline counts include cached tokens, Anthropic's `input_tokens` excludes its separately-reported cache fields — so every adapter normalizes to the total, and the optional `cachedInputTokens`/`cacheCreationInputTokens` carry the split a cost report needs; the provider's own object rides along as `raw` for diagnostics). The engine persists the claim on the assistant Msg at commit time alongside a new `durationMs` (model-call wall-clock, measured before the commit so storage time never inflates it); every ASYNC (remote) tool Msg carries its own `durationMs` — sync local tools record none (they do no I/O, and workerd's request-frozen clock would read 0: recording nothing beats recording a lie), as do a cancelled batch's synthetic results. The anthropic adapter now claims usage from `finalMessage().usage` via `usageFromAnthropic` (exported, mirroring `finishFromStopReason`; partial claims dropped whole; cache fields summed back into the total). `replyStream` accepts an optional third `usage` argument for scripted models. Previously the adapter discarded the SDK's usage on the floor, so per-turn cost accounting was impossible without a proxy in front of the provider.
